# v0.7.0 — Walkthroughs that run themselves

_Released 2026-11-16._

This release makes a guide's whole path something kanbanr can run and check on its own. It also
gives kanbanr and katalogr one shared idea of "where the code is", and fixes the rough edges found
while running the TOGAF and agile guides end to end. 28 items shipped.

## Highlights

### Walkthroughs that run themselves

`kanbanr walkthrough run <runbook>` follows a guide from an empty folder to a cut release with no
one at the keyboard. It drives a Claude Code session on a scratch project, answers Claude's
questions from the runbook, and takes each decision on the scratch board as a scripted person, but
only after checking that the page offers the button the guide names. It pushes only to its own
scratch remotes, and it keeps every capture with a checksum manifest.

A run never stops on a finding. A missing button, a board that disagrees, or a remote that doesn't
match is written down, and the run carries on. At the end, its results wait on your Review page as
one batch, with **Confirm all** and **Reject all** beside the single buttons. Two runbooks ship on
the board, for the TOGAF and the agile guide. `kanbanr walkthrough lint` checks a runbook before
you spend a run on it.

A test of kind `walkthrough` is now automated evidence that such a run proves, never a manual
check.

### A shared position and a view ID

`kanbanr position` prints where the checkout is: the commit, plus a hash of any uncommitted
changes. kanbanr computes it byte for byte as katalogr does. `kanbanr view docs` is the first
answer given for a position, with an ID that repeats whenever the position, the board and the
question repeat. A checkout with line-ending conversion, such as Windows or `core.autocrlf`, now
reads as clean, so both tools agree on it.

### Delegations that work under auto mode

A delegation you grant now comes with the Claude Code permission rule its command needs, so Claude
can use it when Claude Code runs in auto mode. `kanbanr claude permissions --write` adds the
missing rules, after Claude has asked you once.

## Releases and the monitor

- A release whose last stage is the tag reads as **tagged** until its tag workflow's result is
  recorded as passed. Only then does it read as shipped.
- The Releases page offers **Promote to candidate again** when a candidate's release files changed
  after it was prepared.
- The monitor shows which kanbanr version and commit it runs, and warns when the board was last
  written by a newer kanbanr.
- Milestones are listed newest first, in `kanbanr milestone list` and on the Milestones page.
- On the Review page, a disabled Approve or Ratify button says beneath it what is missing and who
  provides it.
- A board's README leads with the project it tracks and links its code repository. kanbanr is
  named below, as the tool that keeps the plan.

## Fixed

- **Ratifying an override.** Ratifying an override at a definition you had already ratified now
  records it and closes the override.
- **Charter after setup.** Agreeing or changing the charter no longer leaves `CLAUDE.md` modified
  on the default branch, which used to make Promote to main refuse the dirty checkout.
- **Sprint close.** Closing a sprint no longer asks about each merged branch. `kanbanr git tidy`
  deletes merged branches locally after one confirmation, and never touches the remote.
- **Agent catch-up merges.** A sprint catch-up merge on a build agent's branch is no longer counted
  as agent work ahead of the board.
- **Docs that were changed.** The `docs_updated` gate also requires the board docs a design links
  under Affects docs to have changed. doctor judges that gate as the move did, so it no longer
  warns about a doc folded just before a move.
- **Edits to flagged texts.** A flagged text stays flagged after an edit, and the Review page shows
  the edit and its diff. A sign-off can't rest on a text changed only to clear its flag.
- **Chores in doctor.** doctor no longer warns that a chore has no Design section.
- **Version in a worktree.** A build in a git worktree is stamped with the commit it was built
  from.
- **More test runners captured.** `kanbanr capture` reads Vitest 5, `pytest -v`, Playwright's list
  reporter and `python -m unittest -v`. It says so when a run printed nothing it can read.
- **Docs guard in worktrees.** The Claude docs guard no longer refuses the book, the changelog or
  the skill inside a linked worktree.
- **Windows fence check.** A walkthrough run is no longer refused on Windows: the fence check accepts
  a folder in Windows' verbatim path form.

## How Claude works with you

- Claude prepares a project's first release before it asks you to promote it: the release files, a
  CHANGELOG chore and the pipeline item.
- Claude keeps a test you named with the kind and name you gave it, and settles test names before
  asking for approval.
- Claude asks how a screen should look even after you've described it, has build agents run the
  formatter and linter before each commit, and checks the queue before telling you what waits.
- The guides recommend agile for a new project, and say that a patch release starts at candidate.

## Upgrading

Run `kanbanr self-update`, then restart any running monitor so it serves the new pages. Nothing on
your board needs migrating.
