# kanbanr 0.1.7 — your own process, designed with Claude and shared on the board

*Released 7 October 2026.*

A process is the stages your work moves through and what each stage asks before work enters it.
Until now, using your own process meant writing a YAML file by hand, and every project kept its own
copy. In this release Claude designs it with you, kanbanr checks it, and your team shares one copy
through the board.

## What's new

- **Design your process in the conversation.** At setup, or any time you say "let's change our
  process", Claude works it out with you in plan mode:
  - It starts from the closest built-in process and asks one question per stage: what must be true
    before work enters it? The choices are only the checks kanbanr can enforce.
  - Anything kanbanr can't see, such as "the architecture board has reviewed it", becomes a named
    sign-off that a person records.
  - The plan shows the checked result as a working agreement and a diagram. Accepting it saves the
    process and applies it.
- **Saved processes, shared through the board.** `kanbanr process save <name>` keeps a process on
  the board, so everyone with the board gets it through its git remote. Add `--personal` to keep it
  in `~/.kanbanr/processes` and carry it to another board.
  - `kanbanr process list` shows every process, its version and the projects using it.
  - Apply one with `kanbanr config workflow --preset <name>`, or start a project with it: `kanbanr
    project init <name> --workflow <name>`.
  - A name is looked up on the board first, then in your personal library, then among the built-in
    processes.
- **Told when a process changes, updated only when you say so.** Saving a new version changes no
  project by itself.
  - `kanbanr process status` and `kanbanr process diff` show where a project stands and what would
    change. `kanbanr process update` takes the new version.
  - `kanbanr doctor`, the start of each Claude session and the monitor's Workflow page all say when
    a newer version is saved.
  - After a save, Claude asks about each project still on an earlier version, one question each.
- **Check a process before applying it.** `kanbanr process check <file>` reports every problem at
  once and changes nothing. `kanbanr process checks` lists every condition a gate can ask for. A
  misspelt check is now named in the error, with the list of valid ones.

## What's fixed

- **Setup on a machine where git has no identity.** The setup's first commit used to fail, and setup
  carried on regardless. Setup now asks whether to use the identity you gave for the board for this
  repository's commits. It's set for that repository only, never globally. If you decline, the first
  commit still goes through with that identity. A failed setup step now stops the rest.
- **Security updates.**
  - The monitor's KaTeX, which mermaid uses to draw maths in diagrams, is pinned to 0.19.0
    ([GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7)).
  - The screenshot tool's rustls goes to 0.23.45
    ([GHSA-2mjx-qc3c-rqvc](https://github.com/advisories/GHSA-2mjx-qc3c-rqvc)). The kanbanr binary
    already had it.

## Upgrade notes

Update with `kanbanr self-update` (macOS, Linux) or by rerunning the installer (Windows). Either
brings the Claude Code skill and the VS Code extension up to date where kanbanr installed them.
Existing boards work unchanged.

Saving a process adds a `processes/` folder to the board. Applying a saved process records it in the
project's `config.yaml`. An older kanbanr keeps both untouched.

See [Processes](../using/processes.md) and [Working with Claude](../using/with-claude.md) for the
details.
