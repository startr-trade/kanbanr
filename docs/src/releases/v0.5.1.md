# kanbanr 0.5.1 — the monitor works on a published port again

*Released 11 November 2026.*

A patch of 0.5.0 with one fix. Upgrade if you run the monitor in a container, or anywhere its port
is published as a different one.

## What's fixed

- **The monitor answers its own page on a published port.** 0.5.0 started answering only its own
  host names, but it counted `localhost`, `127.0.0.1` and `[::1]` only on the port it is bound to.
  In a container the monitor binds 8080, and that port is usually published as another one. kanbanr's
  own `docker-compose.yml` and `make docker-up` publish it as `localhost:18080`, so every page got a
  403. Those three names are now answered on any port. Every other host name is still checked
  exactly as before, and writes still need the token only the monitor's own page receives.

## What this release does not meet

The four points in [0.5.0's notes](v0.5.0.md#what-this-release-does-not-meet) still stand: two
checks not yet made by a person on the monitor, the TOGAF guide not yet confirmed end to end, writes
behind an HTTPS proxy, and one test-only dependency that is unmaintained. 0.6.0 is planned to close
the last three.

## Upgrade notes

1. Update with `kanbanr self-update` (macOS, Linux) or by rerunning the installer (Windows).
2. Restart `kanbanr serve`, or pull and restart the container.
3. If you stay on 0.5.0 in a container, set `KANBANR_ALLOWED_HOSTS=localhost:18080` (your published
   host and port) instead.

Boards need nothing.
