# v0.6.1 — Setup in an existing repository

_Released 2026-11-16._

A patch of [v0.6.0](v0.6.0.md). It contains everything in v0.6.0, plus one fix.

## Fixed

### DEF-067 — Setup can't commit its marker in a repository that already has a commit

Setting up kanbanr in a repository with history used to stop at the setup commit: the git guard and
the git hooks refused setup's own `[no-ref]` commit on the default branch, whether the git model was
on or off, so the `.kanbanr` marker never reached it. Now that one commit goes through, as long as it
stages only `.kanbanr`, `CLAUDE.md` and `.gitignore` and the marker is not committed yet. Any other
commit on the default branch is still refused, and the refusal says what the setup commit may hold.

## Upgrading

Run `kanbanr self-update`. The installed git hooks call `kanbanr` from your PATH, so the fix applies
as soon as the new binary is installed. Nothing on your board changes.
