# kanbanr 0.6.0 — Claude prepares, you confirm; delegated decisions; docs that stay true

*Released 14 November 2026.*

Claude now prepares the evidence for each decision, and you confirm it with one click on the monitor. You can also delegate chosen sign-offs to Claude for a time and review them afterwards. Manual tests and texts to check no longer send you to the terminal, and the release path asks fewer questions.

A board written by 0.6.0 is read by 0.5.x with some limits. See Upgrading.

## What's new

### Deciding

- **Claude prepares each decision's evidence; you confirm.** `kanbanr prepare` fills in a sign-off's note, a promotion's "what you checked", a CI result with its run link, or a ratification's reason. The monitor shows it filled in beside one button. You confirm, edit or reject it, and both the prepared record and your answer are kept. (FTR-034)
- **Delegate chosen decisions to Claude, then review them.** A project picks where decisions are taken. You can grant Claude a delegation for named verdicts, for up to 90 days (14 by default). Every delegated decision returns to the Review page to keep or undo. (FTR-028)
  - Delegations cover forward moves only. If an item has moved back, Claude asks you before it decides or changes anything for it.
  - Only you set the mode, grant a delegation or review one. Release verdicts, withdrawals and ADR verdicts cannot be delegated.
  - Commands: `kanbanr decisions show|mode|propose|grant|revoke|review`, and `--under DLG-n` on `approve`, `ratify` and `signoff`.
  - A release plan warns of delegated decisions you have not yet kept or undone. It does not hold the release.
- **Every decision records where it was taken.** `monitor`, `conversation`, `terminal` or `delegated`. `feature show` and `--json` carry it. Repeating the same decision on unchanged text records nothing and says who recorded it first. (DEF-028)
- **A verdict command run inside a Claude session is refused by kanbanr itself,** not only by the hook. (FTR-028)

### Review page

- **Manual tests are settled on the Review page.** Each manual test not yet green is listed with its requirement and the check to make. You record Passed or Failed there. The board keeps who checked, when, from where and any note. Claude is refused; it can prepare a result you stated, for you to confirm. (DEF-040)
- **Texts to check are settled by Claude.** The docs-folded sign-off no longer asks you to tick each text or type a defect code. Claude settles each one, with why and the revision it checked, and the sign-off appears once none is left. (DEF-039)
- **Docs-folded is offered only when it is true.** It waits until every task is done and every document the Design links is folded. It lapses if the item's branch gets a later commit, and the Review page says which branch moved. (DEF-046, DEF-033)
- **Docs and items that fell behind the code are found.** When docs-folded is offered, the Review page lists linked docs and items that name something the item changed (a flag, route, setting, stage, file) and have not changed since. Each is confirmed or corrected first. `kanbanr drift [--since DATE] [--item CODE] [--json]` lists them for the whole board. It flags what to read and never judges prose. (FTR-013)

### Sprints and setup

- **Work waits for a started sprint.** The first move into a working stage needs the item in a sprint that has started. `kanbanr sprint start` on a later-dated sprint starts it today. `doctor` names a sprint an older version started early. (DEF-041)
- **Setup turns the git model on** when you choose sprints or releases. The built-in agile and design-control processes send a chore through their integrate stage, so every chore path reaches Review. Re-apply the process to take the new path. (DEF-042)
- **Setup asks less and creates less.** Sprints and releases are one question and neither is created until you ask. It reads the name and description from your README or manifest. An unstarted sprint can be edited or removed, and so can an empty release. (FTR-022)
- **`kanbanr sprint unplan ITEM...`** takes items out of their sprint. The board's Sprint filter offers Unscheduled. (DEF-018, FTR-032)
- **Chores take a lighter path** through TOGAF, Scrum, agile and design-control. A chore still records why it exists and how it is verified. (FTR-019)
- **TOGAF fits sprints and releases** without becoming a different process. (FTR-025)

### Releasing

- **Checks that need a push no longer block Promote to main.** A test can say `at: pushed`, `at: cut` or `at: <stage>`. The item's gate does not wait for it; that stage does. (DEF-043)
- **Claude's overrides wait for you.** An override Claude makes sits on the Review page until you ratify it, and the item does not ship until you do. The cut names requirements whose tests were not run and waits for you to accept them. `release promote` and `release cut` take `--accept-untested`. (DEF-043)
- **Promote to candidate fills the changelog section** from what the release ships, or says why it cannot. `kanbanr release notes <V> --changelog <file>` updates it with the notes. (DEF-044)
- **Claude runs git forward itself.** After a fix merges into a release branch, kanbanr names `kanbanr git forward` as Claude's next step. A forward that would conflict changes nothing. Pushing stays yours. (DEF-045)
- **Merged work cannot be carried out of its release.** A promotion is held while a merged item would be carried over for a failed end gate, usually a missing release sign-off. `doctor` names what a release left behind. (DEF-029)
- **A change merged into a promoted release sends it back to candidate,** and the Releases page shows the steps in order. A gate pass carries to a later commit when only docs changed. (DEF-031)
- **Supply chain.** Release and install builds are locked, and each release carries two SBOMs and build attestations. (MNT-004)

### Guides

- **The guides ask about style before a screen is built.** They give one order for a release (promote to main, push main, CI, record the result, cut, push the tag) and design a staged pipeline whose stages rerun alone, with caches for your stack. (DOC-008)
- **New page: Designing CI and the release workflow.** It lists what to settle before a first release. (DOC-007)
- **New guide: TOGAF, sprints and releases with Claude.** It walks through a project in conversation, and names the page and button for every decision: when to approve, how to grant a delegation and set the mode to delegated, and what to set up before the first release. Under Claude Code's auto mode, a delegated sign-off also needs a permission rule for `kanbanr signoff`. (DOC-001)

## Fixed

- **The monitor updates live for a board under a linked folder on macOS.** macOS reports a change under the folder's resolved path, which the watcher did not recognise. (DEF-062)
- **A sprint's release is made from that sprint,** even after an earlier release was brought forward into the previous sprint. Before, the second sprint's release could be branched from the closed sprint and ship without its items. (DEF-059)
- **A crash can no longer leave a board file half-written.** Every file is written to a temporary file and renamed. A leftover `.tmp` file is named by `doctor` after an hour. (DEF-025)
- **A scope binds the agent it was issued to,** not whoever stands in its folder. Revoking a scope no longer traps your own shell. (DEF-027)
- **A scope issued with `--worktree`** no longer tells its agent to claim it. (DEF-023)
- **The monitor refuses to start with writes on at an address other machines can reach,** unless you pass `--allow-remote-writes`. (DEF-026)
- **A batch refuses a field its operation does not take,** instead of ignoring it and reporting success. A bundle that sent such a field now fails; remove the field. (DEF-018)
- **Agents can use a temporary board** for walkthroughs; a real board stays refused. (DEF-015)
- **A release's notes are found** after the notes path changes, and a missing file names every place looked. (DEF-036)
- **The docs gate** no longer passes an item when two board commits share a second. (DEF-035)
- **`drift --since DATE`** starts at the beginning of that day (UTC). (DEF-037)
- **`doctor`** no longer calls `gates/`, `prepared/` or `manual/` stray folders. (DEF-038)
- **The local release gate** is no longer fooled by a cached image layer or by a build agent's records. (MNT-006)

## Does not meet yet

So that you can judge 0.6.0 against the risk you can accept:

- **Walkthrough checks not yet run by a person.** Automated tests pass for each. These manual checks are still open:
  - FTR-034: every sign-off, promotion and CI result is taken with one click and nothing typed.
  - FTR-028: setup proposes delegations for the process and you accept them.
  - DEF-039: an item with drifted docs reaches docs-folded with nothing for you to fill in.
  - DEF-040: a manual test is recorded on the Review page.
  - DEF-045: a release fix reaches the line with no command run by you.
  - DOC-008: the agile walkthrough gets a style question, reaches its cut without a question about push order, and proposes a staged pipeline with caching.
- **Conversation decision mode is not built.** Setting it is refused. Planned in FTR-035.
- **The dry-run move cannot yet see a lapsed docs-folded sign-off.** The real move refuses it.
- **The docs gate does not read docs linked under a design's Affects docs.** Planned in DEF-047.
- **The monitor does not say which kanbanr it runs.** Planned in FTR-036.
- **The guard on who may take a decision is not a security boundary.** kanbanr keeps Claude to your delegations through its own commands and hooks, and makes every departure visible: the recorded origin, commit trailers and the Review list. A hand-written grant is not honoured. But Claude runs as the same user as you and kanbanr has no accounts, so a process that deliberately forges a commit or a file is not stopped.

## Upgrading

1. Update with `kanbanr self-update` (macOS, Linux) or rerun the installer (Windows).
2. Restart `kanbanr serve`.
3. Re-apply your process to give chores the new path (see DEF-042).

A board written by 0.6.0 gains `prepared/`, `manual/` and `decisions.yaml`, and records an origin on decisions. What the changelog states about older versions:

- 0.5.x never reads `decisions.yaml` and acts as the `monitor` mode, which refuses Claude more, not less.
- A 0.5.x that rewrites `releases.yaml` drops the `origin` from release stage changes.
- A process file with `paths` needs 0.6.0; an older kanbanr does not know the key.

The changelog says nothing more on how 0.5.x treats the other new files and fields.
