# kanbanr 0.1.5 — decisions in Claude Code

*Released 4 October 2026.*

You can now run kanbanr entirely from Claude Code, without the browser or a terminal. Ask for work,
and Claude scopes it in a plan for you to accept. Decisions that are waiting come to you one
question at a time. What Claude asks at each step is read from your workflow, so your own process
drives the conversation as well as the presets do.

## Highlights

- **Scope new work in plan mode.** Ask for a feature and Claude reads the charter and the code,
  asks you the choices only you can make (business rules, retention, limits, scope) before writing
  anything, and shows the item's brief as a plan. **Accepting the plan creates the item and records
  your approval of exactly that text.** Anything Claude still had to choose is listed under
  "Choices I made", so accepting is informed.
- **Decide in the conversation.** Say "let's review" (the session start tells you when anything is
  waiting) and each decision comes as one question: Approve, Ratify, Sign off, Accept or Reject a
  design decision, plus "Change it" and "Skip". A design decision Claude drafts is asked about at
  once, not left for you to accept by command.
- **Your workflow decides what is asked.** Claude asks the board what the next stage still needs
  (`kanbanr check --json`) and turns each kind of gap into a draft or a question, the same way for
  every workflow. Tried on the TOGAF preset and on a custom process file: the custom process asked
  *when* the feature happens at its shaping stage; TOGAF, whose gates don't ask, did not.

## What's new

- **`--rev` on `approve`, `ratify` and `signoff`.** A verdict is pinned to the definition you were
  shown, and is refused (recording nothing) if the definition changed in between. Claude always
  passes it; the Review page's buttons send it too. `check --json` and `review --pending --json`
  carry each item's `rev`.
- **A new chapter, [Working with Claude](../using/with-claude.md)**: starting work, deciding, moving
  work, why Claude asks what it asks (a table for every check a gate can ask for), and one feature
  taken through TOGAF stage by stage.

## What's fixed

- **`kanbanr review --pending` listed items that weren't waiting**: ratified and finished ones,
  because it kept its own copy of the rule. It now shows the same queue as the Review page.

- **The container image now runs on Debian 13 "trixie"** with Debian's security updates applied
  at build time. The release refused to push a bookworm image carrying a package Debian had
  already fixed (CVE-2026-103111, `libpcre2-8-0`). The downloadable binaries are unchanged and
  still run on bookworm and newer.

## Upgrade notes

- Update with `kanbanr self-update` (macOS, Linux) or by rerunning the installer (Windows). The
  Claude Code skill updates with the program.
- If you run the monitor from `ghcr.io/startr-trade/kanbanr`, pull `v0.1.5`: it is built on trixie.
- Nothing changes for anyone who approves on the Review page or with the commands. Both still
  work, and a verdict without `--rev` behaves as before.
