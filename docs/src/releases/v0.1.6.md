# kanbanr 0.1.6 — timestamps as instants; releases wait for CI

*Released 5 October 2026.*

A small release with two fixes: one to how kanbanr compares times, and one to how kanbanr itself is
released.

## What's fixed

- **Timestamps are compared as instants, not text.** kanbanr writes times with the trailing zeros
  of the fractional seconds dropped, so two times in the same second can have different lengths.
  Compared as text, `…05.12Z` sorted after `…05.1234Z`, although it is earlier. So an item created
  in the same second as the project's charter could be judged older than the charter, and skip its
  stage gates. Retrospectives and the GitHub issue mirror made the same comparison. All of them now
  compare the times themselves. This release's CI caught it on macOS, whose clock makes the case
  common.

## What changed

- **A release is built only from a commit that passed CI.** v0.1.5 was tagged while CI was still
  running on its commit, and published before CI failed on macOS. The release now checks CI's run
  for the tagged commit before building anything. It waits while the run is in progress, proceeds
  when it passed, and refuses, naming the run, when it failed or never ran.

## Upgrade notes

Nothing to do: update with `kanbanr self-update` (macOS, Linux) or by rerunning the installer
(Windows). Boards are unchanged.
