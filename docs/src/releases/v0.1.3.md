# kanbanr 0.1.3 — decisions get a verdict

*Released 2 October 2026.*

Architecture decisions can now be accepted or rejected by the person who owns them, from the
command line or the Review page. Every release now carries notes like these, and the release's own
installer check runs correctly on every platform.

## Highlights

- **Accept or reject an architecture decision.** A decision drafted with `kanbanr adr new` starts
  as *proposed*; until now the only way to accept it was to edit its file. Now:

  ```bash
  kanbanr adr accept ADR-0007
  kanbanr adr reject ADR-0007 --reason "the browser is enough"
  ```

  The verdict, who gave it and when are written on the decision and appear in the activity log.
  Accepting is refused while a section is unanswered; a rejection keeps its reason. The Review page
  lists proposed decisions beside the definitions waiting for approval, with Accept and Reject.
- **Release notes.** Each release has a notes page in the docs — this is one — and the same text
  opens its GitHub release page.

## What's fixed

- **The release's installer check runs from a folder of its own.** In 0.1.2 it ran inside the
  repository checkout and failed on all four platforms although every install worked.

## Upgrade notes

Nothing to do. Claude now drafts decisions as *proposed* and asks you to accept them; the skill
updates with the program (`kanbanr self-update`, or rerun the installer).
